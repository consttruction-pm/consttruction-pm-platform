SECURITY

Security stated plainly

This page describes what the product actually does today. It is not a certification claim and it does not replace a security review of your own deployment.

Identity and sessions

Access starts with an authenticated account and a server-side session.

Password handling

Passwords are stored as salted scrypt hashes, never in plain text.

Session handling

Sessions use HttpOnly cookies with CSRF protection on state-changing requests.

Sign-in throttling

Repeated failed sign-in attempts are rate limited to slow credential guessing.

Data boundaries

Project data is separated by tenant and project, and enforced on the server.

Tenant and project scope

Every project read and write is scoped to the account's tenant and membership.

Role-based access

Environment and action access follows the roles the server checks, not the buttons the client shows.

Public and private surfaces

Marketing pages are static; project records are only served by the authenticated runtime.
