Sign in and fix login problems

Sign-in uses the username and password issued by your organization. The username is not an email address. Never send your password to anyone; support does not need it.

Sign in and land in the right place

  1. Open the CUBI workspace; when no session is active it shows the sign-in screen at /login.
  2. Enter your username and password. Both fields are required, and the page focuses the username field when it opens.
  3. Choose Sign in. A successful sign-in opens the Personal Workbench, where you choose an environment.

Sign-in always asks for the username and password; an existing session does not silently skip the screen.

Read the message when sign-in is rejected

Username or password is incorrect. The pair did not match; the page does not say which field is wrong. Check Caps Lock and the keyboard layout, and type the username rather than the email address.

Enter your username and password. One of the two fields is empty.

Too many attempts. Wait a few minutes and try again. The server blocked sign-in for a short period after repeated failures, for up to about fifteen minutes. Waiting is part of the protection; repeated attempts extend it.

The workspace service is unreachable. Try again. The request did not reach CUBI. Check the connection and retry.

Reset a password or create an account

Choose Forgot password? on the sign-in page. The page then explains that your CUBI administrator performs a secure reset; there is no self-service reset link to send.

Sign up creates a new account in this installation. Use a username of 3 to 32 characters from letters, digits, dot, underscore or hyphen, starting with a letter or digit; the username is treated case-insensitively. Passwords must be at least 12 characters. The new account starts with least privilege and no project access until an administrator or project owner grants it.

If the username already exists, sign up reports it: sign in instead, or choose another username.

Sessions end, and that is normal

Sessions expire after a fixed lifetime and after a period without activity. The Personal Workbench shows the expiry time under your identity.

When a session ends, sign in again: the Workbench reloads your roles and projects from the server. On a shared device, use Sign out in the Workbench instead of only closing the tab.

Choose the right environment

One account can reach more than one environment. The Personal Workbench shows only what your roles allow, and the server checks the same roles on every request.

Know what each environment is for

CUBI Engineering is the project workspace: projects, WBS, activities, relationships, scheduling, resources and reports. Open Engineering.

CUBI Enterprise covers organization, teams, tasks, approvals, workflows and portfolio for accounts with an enterprise role. Choose Enterprise in the environment selector; it opens the dashboard at /cubi/enterprise/dashboard.

Global Administration is tenant-wide administration of identities, organizations and platform settings; it is reserved for accounts with the global administrator role.

Read the access state, not just the label

Open environment means the server authorized this environment for the current session. Choose it.

Not authorized for this account is a decision, not a temporary failure. Ask an administrator to grant the role the environment requires; retrying will not change it.

Enterprise access could not be verified is not a denial. The server did not answer the access check, so retry; if the message persists, report it with the time and the environment name.

Use the environment selector page

The environment selector lists Engineering and Enterprise availability for the signed-in session, shows how many projects are available, and links into each environment.

It uses the same session as the rest of the product: if it sends you to sign-in, the session has expired. It never opens an environment that the account is not authorized for, and it explains a restricted environment in place.

Open a project and fix access

Projects are scoped to membership inside a tenant. A project that is not listed is not shared with your account, and CUBI does not show a partial or stale copy instead.

Open a project

  1. Open CUBI Engineering or choose Engineering in the Personal Workbench.
  2. Pick a project from the project list. The list contains only projects your account is a member of.
  3. Use the project tabs to switch, or Open (Ctrl+O) in the workspace. The last project reopens in this browser after a refresh.

Why a project is missing

The server scopes every project request to your account. A project that is not listed is either not shared with you or belongs to another tenant.

Ask the project owner or your administrator to add your account to the project; signing up does not grant membership. If a project you used before no longer opens, your access may have been removed, and the workspace asks you to choose another project rather than showing stale data.

Before reporting an access problem, confirm the tenant and roles shown in the Personal Workbench.

Start with a first project

When the account has no project, the workspace offers a first-project form instead of an empty grid. Enter a name of 2 to 120 characters and choose Create and open; the server stores the project before it opens.

The project starts empty. Load or import WBS and activities next, as described in Start work in the workspace. If creation fails, the form keeps the name you entered and shows a reference code; keep that code for support.

The Personal Workbench

The Workbench is the signed-in hub between the public site and the two environments. It is not a third workspace; every action leads into Engineering or Enterprise.

What the Workbench shows

Your identity (Signed in as), tenant, roles and session expiry; the environments you may enter and the reason when one is restricted; your authorized projects and assigned tasks; and the language selector, Help, Account and Sign out controls.

After signing in, the Personal Workbench at /workbench is your hub; you reach it through the workspace entry. It always reflects what the server confirms for the current session.

Use it as the hub

  1. Check Tenant and Roles first when an access problem appears.
  2. Open a project from Authorized projects to go straight into its workspace.
  3. Use Assigned tasks to reach Enterprise task coordination when your role allows it.
  4. Use Help to return to this Help Center and Documentation for reference.
  5. Sign out when you finish on a shared device.

Change your password

Open Account, enter the current password and the new password twice, then submit. A successful change signs out your other sessions, so use the new password everywhere afterwards.

If the two new passwords differ, the form reports the mismatch and changes nothing.

If the Workbench cannot load

The workbench could not be loaded. Please try again. The session or project summary request failed, and nothing is shown as a result. Use Retry; if it fails again, sign out and sign in to renew the session.

Your session has expired. Sign in to continue. The session ended. Sign in again; the Workbench reloads your roles and projects.

Start work in the Engineering workspace

The workspace is a desktop layout: a title bar, a menu bar, a command toolbar, window tabs and panes inside the open project. Nothing is calculated in the browser; dates and totals come from the project server.

Read the shell from top to bottom

Title bar shows the project and the active window. Menu bar groups commands by intent, such as workspace and file, edit, view, project, tools, administration and help. Command toolbar holds the most-used commands for the active window.

A disabled toolbar button states what is needed first, for example selecting an activity or loading project data. Window tabs keep several windows, such as Activities and WBS, inside the same project, and View → Windows reopens a window you closed.

First steps in a project

  1. Open the Activities window and load or import WBS and activities.
  2. Select an activity and review its details; add predecessors and successors in the activity details.
  3. Open Calendars and verify working days, daily hours and dated exceptions.
  4. Run the schedule and check the data date, early and late dates and total float.
  5. Enter progress, then run the schedule again and confirm the stored result before reporting it.

Import and export project data

Project → Import / Export opens the interchange panel. Export sends the loaded activities through the project's registered provider mapping and returns a provider XML document.

Import is a read-only mapping: paste or choose provider XML, and the server maps rows to canonical fields with loss warnings. Import does not change activities, dates or the schedule. Check the mapped row count and the loss warnings before relying on the document.

When a window shows nothing

An empty grid or chart is not a zero result. Each window states what it needs before it can show data; load project data first.

A missing cost, assignment or risk record is shown as empty, never as zero. If a layout is stale or a revision conflict appears, reload so the current revision is used before you repeat the change.

Help inside each window

Every workspace window shares one in-product help surface: the Keyboard shortcuts dialog. It follows the windows you have open, so the commands it lists belong to the work in front of you.

Open the shortcuts dialog

  1. Press F1 anywhere in the workspace.
  2. Or choose the Help button on the command toolbar, or Help → Keyboard shortcuts in the menu bar.
  3. The dialog lists commands for the open windows, their key bindings and their availability.

Find the command for the window you are in

Rows are grouped with workspace actions first, then editing, then view and schedule. Commands tied to a window appear only while that window is open, so the list follows your context.

Use the dialog's own search box to filter by command name or key. An unavailable command states the reason, for example that an activity must be selected in the grid first.

Change or reset a binding

Choose Change next to a command, then press the new chord. A plain letter is rejected because it would interfere with typing; use Ctrl or Alt with a letter, or a function or navigation key.

Conflicting bindings are listed at the top of the dialog. Reset restores one command and Reset all to defaults restores every binding.

Reach the documented topic

Where a command or window has a recorded topic, its row carries a Help link that opens the full topic in a new tab.

The same menu opens About CUBI Workspace (Shift+F12), which describes the scope of the workspace and confirms that data is read from the session's project server. In-product help describes the current window; this Help Center covers access and cross-window workflows.

Common errors and what they mean

Each message below is a real CUBI state. Read the message first, then follow the action it names; no project data is changed by a failed request.

Username or password is incorrect

The credentials did not match. Check the username spelling, Caps Lock and the keyboard layout, and confirm that you are typing the username rather than the email address. After several failures the server throttles sign-in and the page shows a wait message.

Too many attempts

The server temporarily blocked sign-in after repeated failures. Wait for the period named in the message, then try once more. Repeating attempts while the block is active extends it.

The workspace could not be loaded

The session or project request failed and no project data was loaded, so nothing is shown as a result. Use Retry on the page. If it keeps failing, note the time and the reference code the page shows.

No projects are authorized for this account yet

The account is signed in but not a member of any project in this tenant. Ask your administrator or project owner to add your account, then reload the Workbench. A new sign-up never adds access by itself.

Enterprise access is restricted or unverified

Not authorized means the account has no Enterprise entitlement; ask an administrator to grant the enterprise role. Could not be verified means the server did not answer the access check; retry before assuming the environment is unavailable.

Progress on a stale revision is rejected

The project changed after the page loaded the data you are editing. Reload so the current revision is used, then re-enter the change. CUBI does not merge the stale edit silently.

A calendar change did not move dates

A calendar change does not recalculate dates by itself. Run the schedule and verify the returned dates, durations and float together with the stored result.

An import mapped fewer rows than expected

Read the loss warnings returned with the mapping; import is read-only and does not fabricate rows. Correct the source document, then map it again and check the mapped row count.

Contact support with the right details

A precise report resolves access problems faster. CUBI does not ask you to send passwords, session cookies or confidential project data.

Collect these details first

  1. Your username, but never the password.
  2. The tenant and roles shown in the Personal Workbench.
  3. The environment (Engineering or Enterprise) and the window or page.
  4. The project name and project ID from the title bar.
  5. The local time of the problem with the timezone, and whether it repeats.
  6. The exact message or reference code, and what you already tried: Retry, reload, re-run the schedule.

Use the right channel

Start with your CUBI administrator or the owner of the project: they reset passwords securely, grant roles and add project membership.

The Contact page lists the public destinations that exist today. It does not collect or transmit personal or project information, so it cannot open a ticket by itself. When your organization names a support channel, use the list below unchanged.
