# Repository Agent Instructions

**Before every CUBI task, implementation, review or status report:**

1. Read `README.md`.
2. Read `docs/governance/PROJECT_CONTINUITY_PROTOCOL.md` and `docs/governance/PROJECT_STATE_LEDGER.md`.
3. Verify current `main` SHA and read the current Jalal 5 plan plus its exact authoritative workbook; check current GitHub issues, PRs and checks that touch the task.
4. Follow Issue #1486: **native Mobile is mandatory in V1**. Do not follow stale mobile-V2 wording in a proposed crosswalk.
5. Link every scheduled activity to a stable activity ID and GitHub issue/PR. Before coding schedule/control behavior, verify the source-backed calculation contract and add/confirm conformance tests.
6. Separate `main` facts from open-PR proposals. Never report completion or increase a weighted percentage without current-main code, exact-SHA tests, runtime/behavior acceptance and updated traceability.
7. At handoff, update the project state ledger with changed paths, exact commits, checks, unresolved issues and next action. If a required file/check is unavailable, report `BLOCKED / UNKNOWN`; do not guess.

The repository ledger and linked GitHub records are authoritative; conversation memory is not. These instructions are workflow requirements, not proof that any product feature is complete.
