## What changed in the merged slice

- **Schema v3 identity migration** (`card_id_for`), additive and repeatable, verified on the
  real 1030-card / 1539-topic / 9-translation / 513-audit evidence corpus (SQLite copy) and
  on PostgreSQL: no orphans, no lost revisions or audits, content multiset unchanged, all
  four immutability triggers recreated. See `MIGRATION-v2-v3-CHECK.md`.
- **Schema v4 `assistant_request`**: `(tenant,user,workflow,request_key)` primary key with a
  payload fingerprint and run id. Replay works beyond the previous 50-run scan window; the
  same key with a different locale conflicts with `WORKFLOW_IDEMPOTENCY_CONFLICT`; the record
  and the business write commit in one transaction. The legacy scan remains as fallback for
  pre-v4 databases.
- **Optimistic concurrency** on cards and translations (`expected_version`, insert-only `0`,
  `409`-shaped `*_VERSION_CONFLICT` errors, revision snapshots preserving actor/time).
- **Readable history**: cursor-paginated card events, tenant/project-scoped, no cross-tenant
  leakage; database-level audit/event immutability (SQLite triggers, PostgreSQL PL/pgSQL
  `RAISE EXCEPTION`).
- **PostgreSQL store** (`postgres_store.py`, 616 lines) with the actual adapters: `?`→`%s`
  translation, `INSERT OR IGNORE`→`ON CONFLICT DO NOTHING`, identity columns, deferrable FK
  used only for the identity migration, advisory locks `pg_advisory_xact_lock(hashtextextended(…))`
  in `_lock_card`/`_lock_translation`, savepoint-aware transactions.
- **Concurrency defect found by the new tests, not by review:** SQLite serialised writers via
  `BEGIN IMMEDIATE`; PostgreSQL did not. Two concurrent writers could both report success.
  Fixed with the lock hooks above; the two-thread race test now proves exactly one winner.
- **Workflow defects fixed:** approval tokens are bound to actor, run and review hash (a
  foreign admin could previously spend a token); unkeyed `start()` calls in the same second
  no longer collide.
- **Ingestion honesty:** a partial run is recorded as `partial`, lists failures and audits
  `partial`; it never reports success. `tools/knowledge_inventory.py` read validated counts
  from the publication map and reported 0 validated for 1030 validated cards; fixed and
  regression-tested, with a hash check that measurement mutates nothing.
