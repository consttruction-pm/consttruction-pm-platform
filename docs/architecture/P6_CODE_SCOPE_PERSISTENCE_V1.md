# P6 Code Scope Persistence Boundary v1\n\nThis slice persists typed P6 code definitions and their allowed values with explicit GLOBAL, PROJECT and EPS scope kinds. It is provider-neutral metadata persistence only; it does not assign codes to activities/resources, calculate schedule/resource/cost semantics, or perform code inheritance.\n\nIdentity is tenant/project/code_id at a project revision. Identical writes replay idempotently; changed definitions and stale revisions fail closed. SQLite and PostgreSQL implement the same repository contract and the application service owns transactions.\n\nAssignments and provider-specific import/export mapping remain subsequent slices and must consume this boundary rather than creating a second code registry.\n
