# P6 Resource Spread Persistence Boundary v1\n\n## Purpose\nPersist P6 resource-spread future-period buckets as typed, tenant/project/revision-scoped data.\n\n## Boundary\nThis slice stores resource spread buckets only. It does not calculate resource demand, leveling, costs, rates, calendar conversion, allocation, or financial semantics. Shared Core remains authoritative for those semantics.\n\nEach bucket is immutable by (tenant_id, project_id, spread_id, period_id) at a project revision. Identical writes are idempotent; changed definitions or stale revisions fail closed.\n\nThe value is stored as a decimal string to preserve precision. metric=UNITS may carry an explicit unit; metric=COST may carry an explicit currency. No unit or currency conversion is performed.\n\n## Persistence\n- SQLite repository for deterministic local/regression coverage.\n- PostgreSQL repository with the same contract.\n- Application service owns the transaction boundary.\n- Reads and writes enforce tenant/project/project-revision scope.\n\n## Verification\nFocused tests cover round trip, deterministic ordering, scope isolation, stale revision rejection, idempotent replay, immutability and typed unit/currency guards.\n\n## Next dependency\nImport/export adapters may map provider-specific resource-spread rows into these buckets through the existing P6 interchange mapping and typed-value boundaries. They must not add calculation semantics here.\n
