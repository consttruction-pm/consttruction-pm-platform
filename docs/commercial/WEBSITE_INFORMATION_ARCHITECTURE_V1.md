# Website Information Architecture & Conversion Specification v1.0

**Date:** 2026-09-25  
**Status:** Planning baseline

## 1. Product website objective

The website is the commercial front door of the product. It must:
- explain the product in under 30 seconds;
- establish specialist credibility;
- demonstrate depth beyond generic PM software;
- convert qualified construction professionals into demo/pilot/early-access leads;
- support Persian and English;
- support SEO without degrading the specialist message.

Hero:
**Construction Project Management & Project Controls — connected from plan to field.**

Supporting line:
**Schedule, progress, cost, resources, documents, contracts, field data and accountable AI in one connected project environment.**

CTA:
**Book a Demo**
Secondary:
**Join Early Access**

## 4. Conversion proof hierarchy

1. Product demonstration.
2. Workflow proof.
3. Calculation/technical credibility.
4. Interoperability proof.
5. Security/offline proof.
6. Customer evidence.
7. Pricing/pilot clarity.

Do not lead with a giant feature checklist.

## 5. Demo design

Demo project should be a realistic construction project with:
- WBS;
- activities;
- multiple calendars;
- FS/SS/FF/SF relationships;
- resources;
- cost;
- baseline;
- actual progress;
- EVM/Earned Schedule;
- resource histogram;
- RFI;
- submittal;
- document revisions;
- change order;
- claim evidence;
- field update;
- executive dashboard;
- AI question with cited sources and an approval-controlled action proposal.

## 6. Lead form

Minimum fields:
- Name
- Business email
- Company
- Role
- Country
- Number of active projects
- Approximate project size
- Current tools
- Primary problem
- Preferred language

Optional:
- project file/sample;
- demo scenario.

## 8. SEO strategy

Build topic clusters around:
- Primavera P6 alternatives;
- MS Project alternatives;
- construction scheduling;
- project controls;
- EVM;
- earned schedule;
- construction progress tracking;
- resource/cost control;
- RFI/submittal/document control;
- change order/claims;
- construction field reporting;
- construction AI.

SEO copy must be educational and evidence-led, not keyword stuffing.

## 9. Localization

Persian and English are first-class experiences.

Rules:
- no hard-coded visible text;
- separate language resources;
- locale-aware dates;
- Jalali/Gregorian display;
- local number formatting;
- RTL/LTR support;
- translated SEO metadata;
- localized screenshots where useful.

## 10. Technical web requirements

The website should share:
- product design tokens;
- analytics contract;
- authentication handoff where applicable;
- documentation links;
- status page;
- accessibility baseline;
- performance budget;
- secure form handling.

The website must not implement authoritative scheduling, EVM, resource, or cost calculations independently of Shared Core.

## 11. Website release phases

### Phase A
Brand placeholder + landing page + early access.

### Phase B
Full product site + interactive demo + resources.

### Phase C
Pricing + pilot onboarding + comparison center.

### Phase D
Case studies + regional localization + partner/integration pages.
